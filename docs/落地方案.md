# 轻音 LiteTalk · 落地方案

> 版本 v1.0 · 2026-10-13 · 基于《大致架构.md》《主题色.md》《参考设计.png》

---

## 0. 项目范围

**定位**：桌面语音联机应用（类 Oopz，裁剪版）。客户端负责全部音频处理，服务器只做 SFU 转发 + 信令 + TURN 穿透。

| 本期做（MVP） | 本期不做 |
|---|---|
| 邮箱注册 / 登录 / 找回密码 | 视频、屏幕共享、录制 |
| 服务器（群组）+ 文字/语音频道 | **头像系统（明确禁止，含首字母头像）** |
| ≤10 人/房 语音通话（SFU） | 服务端混音 / 转码 |
| 好友列表 + 在线状态 | 移动端 |
| 文字频道聊天（持久化） | 消息全局搜索 |
| 静音 / 耳聋 / 独立用户音量 | 机器人 / 第三方集成 |
| 系统托盘后台保活、基础设置 | |

## 1. 总体架构

```
┌──────────────────────────┐                            ┌────────────────────────────────────┐
│  LiteTalk 客户端          │      HTTPS / WSS (443)     │  Nginx 1.30（TLS 终结 + 反代）       │
│  Wails v3 + Vue 3        │ ◄────────────────────────► │    ├─ /api/* → Go 单体 :8077 (REST)│
│  ├ 前端：仅渲染 UI        │                            │    └─ /ws    → Go 单体 :8077 (信令)│
│  └ Go 后端（音频全链路）:  │ ◄──── SRTP / Opus (UDP) ─► │  Go 单体：SFU 转发 ICE-Lite :7845  │
│    采集→降噪→Opus→RTP    │ ◄──── TURN 中继兜底 ──────► │  coturn :3478 + 49152-49200/udp  │
└──────────────────────────┘                            │  MySQL 9.7 / Redis 8（仅本机）      │
                                                        └────────────────────────────────────┘
                              RockyLinux 9.5 单机部署
```

三条数据通路：

1. **账号/业务**：客户端 → HTTPS → Nginx → Go REST → MySQL/Redis
2. **信令**：客户端 → WSS → Go WebSocket（入房、SDP/ICE 中继、状态广播、聊天）
3. **媒体**：客户端 → SRTP/UDP → SFU（直连优先，不通走 coturn TURN 中继）

## 2. 对《大致架构.md》的关键修正

以下条目在动手前必须修正，否则会踩坑：

| # | 原文档说法 | 实际情况 | 对策 |
|---|---|---|---|
| 1 | "Pion 完整支持 Opus 编解码" | **Pion 只做 RTP 封包/解包，不含 Opus 编码器**。PCM→Opus 必须引入 libopus（`gopkg.in/hraban/opus.v2`，CGo） | 客户端构建链必须支持 CGo；预编译 libopus 静态库入仓 `client/third_party/` |
| 2 | "SFU 选型 Kraken（推荐）" | 未能查证到名为 Kraken 的成熟 Go 音频 SFU 项目，疑似信息源有误 | 二选一：**自研 Pion SFU（本方案推荐）** 或 LiveKit，详见 §3 |
| 3 | "使用 Wails v3" | Wails v3 仍处于 **alpha**，API 有破坏性变更可能 | **已决策（2026-10-13）：直接使用 v2 稳定版**；托盘用 `getlantern/systray`，关窗拦截用 v2 的 `OnBeforeClose(ctx) bool` |
| 4 | "rnnoise-go 从 8k 到 48k 原生支持" | 纯 Go 移植的推理性能未经实测验证 | M1 里程碑设性能验收：单核 CPU <5% @48kHz/10ms 帧；不达标退回 CGo rnnoise + `runtime.LockOSThread()` |
| 5 | "Pion 零 CGo 依赖" | 仅 WebRTC 部分成立。PortAudio 和 libopus 都是 C 库，**客户端整体必然带 CGo** | Windows 用 MSYS2/MinGW-w64 构建；CI 用 GitHub Actions windows runner 出包 |
| 6 | 回调约束 | 补充：Go 侧回调经 CGo 进入 PortAudio 实时线程，同样**禁止分配内存、阻塞、调用 runtime** | 所有跨线程数据走无锁 RingBuffer + sync.Pool，M1 做静态检查与压测 |

## 3. 技术选型决策表

| 模块 | 选型 | 理由 | 风险 / 备选 |
|---|---|---|---|
| 桌面壳 | **Wails v2 稳定版（已确认，放弃 v3 alpha）** | 原生 WebView，内存 ~10MB，启动 <0.5s；API 稳定、文档/社区成熟 | v2 无内置托盘 → `getlantern/systray`；窗口层做接口封装，v3 正式发布后再评估迁移 |
| 前端框架 | Vue 3 + Vite + TS + Pinia + Vue Router | 生态成熟，与 Wails 模板契合 | — |
| 样式方案 | **手写 CSS 变量设计系统**（不引 Tailwind） | 主题色只有 4 色，token 化更干净，避免工具类与设计系统冲突 | — |
| 图标 | `lucide-vue-next`（原型用 lucide UMD） | 需求指定 | 禁止 emoji 充当图标 |
| 前端动效 | CSS transition/keyframes + Vue `<Transition>` | 该 UI 复杂度无需重型动画库 | 复杂编排再引入 GSAP |
| 音频采集 | `drgolem/go-portaudio`（M1 验证，否则 `gordonklaus/portaudio`） | 跨平台 WASAPI/ALSA | CGo，需 MinGW |
| 降噪 + VAD | `VoiceBlender/rnnoise-go` | 纯 Go、自带语音概率输出可复用为 VAD | 性能不达标 → CGo rnnoise |
| Opus 编解码 | `hraban/opus.v2`（libopus） | 事实标准，支持带内 FEC 与 PLC | CGo，预编译入库 |
| WebRTC 协议栈 | `pion/webrtc` v4 | 纯 Go，支持 ICE-Lite / UDP Mux | — |
| **SFU** | **自研 Pion SFU（已确认）** | 纯音频 ≤10 人/房，转发逻辑约 1.5k 行；与信令同进程，单二进制部署，运维最简 | RTC 接入层做接口抽象，保留切 LiveKit 的退路 |
| TURN | coturn（REST API 短期凭证） | 成熟稳定，与文档一致 | — |
| 信令 + 业务 API | **Go 单体（已确认）**（HTTP 路由用 chi，WebSocket 用 coder/websocket） | 单一语言、单一部署单元；服务器的 PHP 8.5 留给既有站点，不参与本项目 | — |
| 数据库 | MySQL 9.7 + `go-sql-driver/mysql` + `sqlx` + `golang-migrate` | 轻量直写 SQL，schema 可迁移管理 | — |
| 缓存/状态 | Redis 8 + `go-redis` | 在线状态、验证码、限流、刷新令牌 | — |
| 鉴权 | 邮箱+密码，bcrypt(cost=12)，Access JWT（HS256，2h）+ Refresh Token（Redis，30d 滑动旋转） | 单服务 HS256 足够 | — |
| 邮件 | 阿里云邮件推送 或 现有邮箱 SMTP | 注册/找回密码验证码 | 发件频控防轰炸 |

## 4. 客户端设计

### 4.1 模块划分

```
client/
├── main.go / app.go                 # Wails 入口、窗口/托盘生命周期
├── frontend/                        # Vue 3 + Vite + TS（只渲染 UI）
└── internal/
    ├── audio/                       # 采集、播放、RingBuffer、混音
    │   ├── capture.go               # PortAudio 输入（48k/mono/20ms）
    │   ├── playback.go              # PortAudio 输出 + 多路混音
    │   ├── ringbuffer.go            # 无锁环形缓冲（原子操作）
    │   └── dsp.go                   # RNNoise 降噪 + VAD + 增益
    ├── codec/opus.go                # libopus 编解码封装（FEC/PLC/DTX）
    ├── rtc/peer.go                  # Pion PeerConnection 管理（对 SFU 单条 PC）
    ├── signaling/ws.go              # WSS 客户端 + 自动重连 + 心跳
    ├── api/client.go                # REST 客户端 + token 刷新
    ├── tray/tray.go                 # 系统托盘
    └── state/store.go               # Go 侧状态，经 Wails Events 推给前端
```

### 4.2 音频管线

**上行**：`PortAudio(48k mono int16, 20ms/960帧) → 无锁 RingBuffer → RNNoise(10ms×2) → VAD → libopus(48k mono, 32kbps, useinbandfec=1, DTX=on) → RTP 打包 → Pion → SFU`

**下行（每远端一路）**：`JitterBuffer(60–120ms 自适应) → libopus 解码（丢包走 PLC）→ float32 混音器（每用户独立增益/静音）→ PortAudio 输出`

| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 48000 Hz | Opus 全频段 |
| 帧长 | 20 ms | 延迟与开销的平衡点 |
| 码率 | 32 kbps | 10 人房：下行 ≈ 288 kbps |
| FEC | 开启 | 丢包保命 |
| DTX | 开启 | 静音不发包，省带宽 |
| 声道 | mono | 语音场景足够 |

### 4.3 硬约束（M1 验收项）

- PortAudio 回调内：**零堆分配、零锁、零阻塞**；缓冲全部 `sync.Pool` 预分配
- 采集线程 → 编码 goroutine 之间只经无锁 RingBuffer（容量 ≥ 200ms）
- 每远端解码/混音在独立 goroutine，单路卡顿不拖垮整体
- 目标端到端延迟（采集→对端播放）LAN < 80ms

### 4.4 说话状态

客户端本地 VAD（RNNoise 返回的语音概率）→ 节流 200ms → WS `voice.state {speaking}` → 服务器广播给房间 → 各端 UI 驱动声波动画。**服务器不解析任何音频内容。**

### 4.5 窗口与托盘

- 无边框窗口 + 36px 自定义标题栏（拖拽区 + 最小化/最大化/关闭）
- Wails v2 用 `OnBeforeClose(ctx) bool` 返回 `true` 拦截关闭 → `runtime.WindowHide(ctx)` 隐藏到托盘；托盘用 `getlantern/systray`，菜单：显示窗口 / 静音 / 退出
- v2 不支持窗口销毁后重建，后台挂机采用**隐藏窗口**方案：WebView 保留但停止重绘，Go 进程保活音频流（VAD 动态启停采集），目标后台内存 30–60MB

### 4.6 前端状态

Pinia stores：`auth / servers / channels / voice / friends / chat / settings`。
Go → 前端事件：`voice:peer-join`、`voice:peer-leave`、`voice:speaking`、`voice:state`、`rtc:latency`、`chat:message`；
前端 → Go 方法：`JoinChannel / LeaveChannel / SetMute / SetDeafen / SetPeerVolume / SendChat`。

## 5. 服务端设计

### 5.1 进程内模块

```
server/
├── cmd/server/main.go
├── internal/
│   ├── api/          # REST：auth / users / friends / servers / channels / rtc
│   ├── ws/           # 信令 hub：连接管理、房间广播
│   ├── sfu/          # Pion：ICE-Lite、房间路由、RTP 透传
│   ├── store/        # MySQL（sqlx）+ Redis
│   ├── auth/         # JWT、bcrypt、验证码
│   └── mailer/       # SMTP 发信
├── migrations/       # golang-migrate
└── deploy/           # nginx / systemd / coturn 配置
```

### 5.2 SFU 核心设计

- **ICE-Lite + 单 UDP Mux**：`SettingEngine.SetLite(true)` + `SetICEUDPMux(7845)` + `SetNAT1To1IPs(公网IP)`——SFU 侧只需开放 **1 个 UDP 端口**
- 每个客户端与 SFU 之间**只有一条 PeerConnection**（一条上行 track，N 条下行 track）
- 房间路由：`inboundTrack.SSRC → 同房间其他 peer 的 outboundTrack`，RTP 透传时按每个订阅者重写 SSRC/Seq/Timestamp（Pion `TrackLocalStaticRTP` 模式）
- **不解码、不混音、不转码**；RTCP 仅转发 SR/RR 供客户端算延迟，NACK 按需透传（音频主要靠 FEC+PLC 兜底）
- 房间人数上限配置化（默认 10），超限拒绝加入
- 客户端静音 = **停止上行发包**（配合 DTX），播放端自动进入舒适噪声

### 5.3 信令协议（WSS）

连接：`wss://<domain>/ws?token=<access_jwt>`，信封格式：

```json
{ "type": "voice.state", "data": { ... }, "ts": 1734500000000 }
```

| type | 方向 | data | 说明 |
|---|---|---|---|
| `hello` | S→C | `{user, servers, friends, presence}` | 鉴权成功后下发全量初始数据 |
| `channel.join` | C→S | `{channel_id}` | 加入语音频道 |
| `channel.joined` | S→C | `{channel_id, members[], self}` | 房间成员全量 |
| `channel.leave` / `channel.peer_left` | C→S / S→C | `{channel_id}` / `{channel_id, user_id}` | |
| `rtc.offer` / `rtc.answer` | 双向 | `{sdp}` | 与 SFU 的 SDP 交换 |
| `rtc.ice` | 双向 | `{candidate}` | Trickle ICE |
| `voice.state` | C→S→广播 | `{speaking?, mute?, deafen?}` | 说话/静音/耳聋状态 |
| `chat.send` | C→S | `{channel_id, content}` | ≤2000 字，频控 |
| `chat.message` | S→C | `{id, channel_id, user, content, ts}` | 广播 + 落库 |
| `presence.update` | S→C | `{user_id, status, channel_id?}` | 好友在线状态 |
| `friend.request` / `friend.accept` | S→C | `{...}` | 好友事件实时推送 |
| `error` | S→C | `{code, message}` | |

### 5.4 REST API（前缀 `/api/v1`）

| 分组 | 方法与路径 | 说明 |
|---|---|---|
| 认证 | `POST /auth/register` | 昵称+邮箱+密码+邮箱验证码 |
| | `POST /auth/login` | 邮箱+密码 → access+refresh |
| | `POST /auth/refresh` | 旋转刷新令牌 |
| | `POST /auth/logout` | 吊销 refresh |
| | `POST /auth/email-code` | 发验证码（用途 register/reset，60s 间隔） |
| | `POST /auth/password/reset` | 邮箱+验证码+新密码 |
| 用户 | `GET /users/me` · `PATCH /users/me` | 昵称可改，无头像字段 |
| 好友 | `GET /friends` · `POST /friends/requests`（按 `昵称#tag` 添加）· `POST /friends/requests/{id}/accept` · `DELETE /friends/{id}` | |
| 服务器 | `POST /servers` · `GET /servers` · `PATCH /servers/{id}` · `DELETE /servers/{id}` · `POST /servers/join`（邀请码）· `GET /servers/{id}/members` | 图标为预设 Lucide 图标+颜色 |
| 频道 | `POST /servers/{id}/channels` · `PATCH /channels/{id}` · `DELETE /channels/{id}` | type: text/voice |
| 消息 | `GET /channels/{id}/messages?before_id=` | 分页 50 条 |
| RTC | `POST /rtc/credentials` | 返回 ICE servers（STUN + TURN 短期凭证，HMAC-SHA1，12h 有效） |

### 5.5 通话建立时序

```
Client A                    Go 单体 (API+WS+SFU)                  coturn
   │  POST /rtc/credentials ──►│ (签发 TURN 短期凭证)                │
   │◄──── iceServers ──────────│                                    │
   │  WSS /ws?token=... ──────►│ 鉴权，下发 hello                    │
   │  channel.join ───────────►│ 校验频道权限，返回成员列表           │
   │  rtc.offer ──────────────►│ SFU: ICE-Lite answer               │
   │◄──── rtc.answer ──────────│                                    │
   │  rtc.ice (trickle) ◄─────►│ 连通性检查（host→srflx→relay 依次） ─►│
   │ ══════ SRTP/Opus 媒体流 ══►│ 房间路由表登记，向其他成员透传       │
```

## 7. 部署方案（RockyLinux 9.5 单机）

### 7.1 端口与安全组

| 端口 | 协议 | 用途 | 暴露 |
|---|---|---|---|
| 443 | TCP | Nginx：REST + WSS | 公网 |
| 3478 | TCP/UDP | coturn STUN/TURN | 公网 |
| 5349 | TCP | TURNS（可选） | 公网 |
| 49152-49200 | UDP | coturn relay 端口段（小规模收窄） | 公网 |
| 7845 | UDP | SFU ICE-Lite UDP Mux | 公网 |
| 8077 | TCP | Go 单体 | 仅 127.0.0.1 |
| 3306 / 6379 | TCP | MySQL / Redis | 仅 127.0.0.1 |

### 7.2 Nginx（`/etc/nginx/conf.d/litetalk.conf`，既有 PHP 站点互不影响）

```nginx
server {
    listen 443 ssl http2;
    server_name litetalk.example.com;
    # ssl_certificate / ssl_certificate_key 由 acme.sh 签发

    location /api/ {
        proxy_pass http://127.0.0.1:8077;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto https;
    }
    location /ws {
        proxy_pass http://127.0.0.1:8077;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

### 7.3 进程管理

- `litetalk.service`：systemd，`Restart=always`，日志走 journald + logrotate 按周轮转
- `coturn`：沿用文档的 turnserver.conf（`min-port=49152` `max-port=49200` 收窄端口段），改 `use-auth-secret` + TURN REST API，凭证由 Go 服务端动态签发
- MySQL：`mysqldump` 每日 cron 备份保留 14 天；Redis 开 AOF

### 7.4 上线检查清单

acme.sh 证书自动续期 ✓ firewalld 放行 ✓ 安全组 ✓ journald 磁盘配额（`SystemMaxUse=500M`）✓ 备份脚本 ✓ SFU 公网 IP 配置 ✓ TURN 凭证联调 ✓

## 8. 安全要点

- 媒体面：强制 DTLS-SRTP；TURN 凭证 12h 过期，防中继滥用
- 账号面：bcrypt(12)；验证码 6 位/10min/错误 5 次作废；登录限流 5 次/min/IP；发码 60s 间隔 + 同邮箱 5 次/日
- 会话面：Access JWT 2h；Refresh Token Redis 存储、每次刷新旋转、旧令牌立即吊销
- 应用面：全部 SQL 参数化；聊天内容长度/频率限制；WS 首包鉴权失败即断连；审计日志记录登录与密码重置
- CORS 仅放行 `wails://` 与运维域名

### 9.2 无头像用户视觉方案（核心差异点）

- **语音卡片**：中央为「声波球」——76px 圆形，底为身份色 10% 填充，内部 5 根波形条；说话时描边 2px 身份色 + 外发光 + 波形律动；静音时球内显示 `mic-off` 图标。下方姓名 + 状态胶囊（已静音/已耳聋）
- **身份色**：`identity = palette[hash(user_id) % 4]`，仅用于光环/波形，**不构成头像**
- **好友列表**：状态圆点（在线绿/离开橙/忙碌红/离线灰）+ 昵称 + 所在频道文字，无圆形头像位
- **服务器图标**：创建时从预设 Lucide 图标 + 品牌色系底色中选择（存 `icon_name/icon_color`），不用上传图

### 9.3 页面与图标映射

页面：登录 / 注册 / 找回密码 / 主界面（语音房间 + 文字聊天）/ 设置（账号、音频设备、语音、快捷键、关于）/ 好友请求 / 创建·加入服务器。

Lucide 映射：品牌 `audio-waveform`、语音房 `audio-lines`、文字聊天 `message-circle`、频道 `hash / volume-2 / lock / eye`、公告 `pin`、麦克风 `mic / mic-off`、耳机 `headphones / headphone-off`、设置 `settings`、挂断 `phone-off`、好友 `users / user-plus`、搜索 `search`、延迟 `wifi`、更多 `more-horizontal`、发送 `send`、密码可见 `eye / eye-off`、窗口控制 `minus / square / x`。

### 9.4 文案规范

按钮/标签 ≤6 字（"加入频道""发送验证码"）；不写宣传性长句、不写"智能/AI 驱动"类修饰；空状态一句话给出动作（"邀请朋友加入频道"）；emoji 一律禁用。
